Puggle (*Pre-Verification Untrusted Grammar & Goal Linguistic Engine*) is the
isolated Type 6 neurosymbolic auto-formalisation front-end for ECHIDNA. It
constructs bound signature ASTs under relational constraints, audits semantic
round trips, and serialises a frozen handoff. Puggle and all model output remain
outside ECHIDNA's Trusted Computing Base (TCB).

[IMPORTANT]
====
The implementation targets formal *signatures*, not arbitrary Lean, Agda, or
SMT-LIB proof scripts. A semantic quorum is evidence for a handoff decision; it
is not a proof that informal and formal meanings are identical. ECHIDNA remains
responsible for its own proof checking and input authentication.
====

== Architecture

The generation path is `Neural[Symbolic]`:

. A token model returns a vocabulary-sized logits vector.
. `LogitProcessor` speculatively applies every token to a cloned
  `KanrenConstraint`. Unknown tokens, invalid phase transitions, duplicate
  binders, unbound variables, target-invalid sorts, and unification failures
  receive `−∞` logits.
. Only the selected continuation is committed. The microKanren substrate uses
  persistent substitutions, an occurs check, structural unification, fresh
  variables, and fairly interleaved streams.
. A complete AST is independently validated and rendered for its target. Its
  unambiguous length-prefixed canonical form is hashed with BLAKE3.
. Three or five deformaliser agents run asynchronously. The semantic metric
  compares each English result with the *exact original input*, not a repair
  prompt.
. Distances are rounded to integer millionths. The odd-sized agent median is
  the canonical Paxos proposal; consequently a median strictly below `0.05`
  also establishes a majority of below-threshold semantic votes.
. Paxos acceptor actors execute prepare/promise and accept/accepted phases.
  Proposers use ordered unique ballots and carry forward the highest accepted
  value. A majority accept quorum authorises freezing.
. Rejection produces a bounded, feedback-directed repair prompt. Exhausting the
  attempt budget returns an error and emits no ECHIDNA handoff.

== Build and test

Requirements: Rust 1.85 or newer, the `capnp` compiler, and Idris2 for the ABI
check. Candle support is opt-in so the relational and consensus tests do not
need an ML runtime.

[source,bash]
----
cargo build
cargo test
cargo clippy --all-targets -- -D warnings
cargo check --features candle
idris2 --typecheck src/abi/puggle-abi.ipkg
----

Equivalent focused recipes are `just puggle-build`, `just puggle-test`,
`just puggle-check`, `just puggle-check-candle`, and `just puggle-abi-check`.
The recipes use `--locked`; generate and review `Cargo.lock` when changing
dependencies.

== Semantic metric

`JaccardMetric` computes `1 − |A ∩ B| / |A ∪ B|` and returns both omitted and
introduced concepts for repair. Empty concept sets are rejected, preventing two
vacuous texts from passing as equivalent.

The deterministic local extractor supports explicit namespaced concepts such
as `wn:group.n.01` and `msc:20-XX`, plus normalised lexical concepts. It is not
presented as a complete WordNet implementation. Deployments can inject a full
WordNet/MSC2020 extractor through `ConceptExtractor`, or an embedding metric
through `SemanticMetric`, without changing Paxos or the freeze contract.

== HTTP boundary

[source,bash]
----
PUGGLE_ADDR=0.0.0.0:3000 cargo run -- serve
----

`GET /health` reports liveness. `POST /v1/freeze` accepts an original text and
an untrusted structured candidate. This endpoint deliberately does not pretend
that a model is installed; neural formalisation is available through the
`Formaliser` trait and `SemanticGatekeeper::run` library pipeline.

This request is rejected with `422`: the default English renderers do not
produce the concepts "commutative" or "group", so the semantic audit fails.

[source,json]
----
{
  "original": "commutative group operation",
  "candidate": {
    "target": "lean",
    "name": "operation",
    "bindings": [],
    "result": { "Named": "Nat" }
  }
}
----

To try a successful handoff with the default renderers, use this request. It
matches their lexical concepts, including the canonical sort token `n3:Nat`:

[source,json]
----
{
  "original": "The lean signature maps declaration of sort n3:Nat, accepts of sort n3:Nat, returns of sort n3:Nat, maps of sort n3:Nat to n3:Nat.",
  "candidate": {
    "target": "lean",
    "name": "signature",
    "bindings": [
      { "name": "declaration", "sort": { "Named": "Nat" } },
      { "name": "accepts", "sort": { "Named": "Nat" } },
      { "name": "returns", "sort": { "Named": "Nat" } },
      { "name": "maps", "sort": { "Named": "Nat" } }
    ],
    "result": { "Named": "Nat" }
  }
}
----

A successful response has content type `application/x-capnp`, an
`x-puggle-ast-hash` header, and a `FormalSignature` body. Invalid or drifted
candidates receive `422` and produce no handoff. The default English agents are
reference renderers; inject independent deformalisers for a production RTT
audit.

== ABI and trust boundary

The Idris2 `FrozenSpec` record has no constructor path that takes merely an AST
and receipt. It additionally requires:

* `QuorumReached` indexed by the receipt's exact acceptor and node counts;
* a strict `LT distance 50000` proof; and
* equality between the AST digest and receipt digest.

All three proofs are mandatory at type checking. The quorum witness is retained
at runtime for `quorumOf`; the drift and hash-binding proofs are erased. The
module uses `%default total` and no postulates or proof escape hatches. The Rust
type also keeps its constructor and fields private, and the wire encoder
accepts no bare AST.
